## Locked decisions (two sharpened by review)

1. **Settle-before-serve** — sequence gains pre-settle request validation and a
   persisted-response replay contract (G2).
2. **Parallel `/v2/` route + 90-day sunset** — legacy route is rewired through
   the v2 settlement pipeline at Stage 4 so the serve-before-settlement hole
   does not outlive Stage 4 (G1); sunset may collapse to a hard cut per Stage 0
   traffic data.
3. **Facilitator-authoritative verification** — local verification demoted from
   gatekeeper AND promoted to quota guard: structural hard gate + EOA-only
   ecrecover prefilter; EIP-6492 (magic-suffix detect) / EIP-1271 (contract
   payer) pass through to the facilitator (G4).
4. **Permit2 cut** — USDC has native EIP-3009 on Base/Sepolia; Permit2 doubles
   the crypto surface for zero demand.

## Binding gap-fixes

- **G1** Legacy keeps the hole through sunset → at Stage 4 rewire legacy
  through the same structural-gate → verify → claim → settle → execute pipeline
  behind the old codec; RFC 8594 `Deprecation`/`Sunset` headers on legacy
  responses; Stage 0 measures live legacy paid traffic (~zero ⇒ hard-cut at
  Stage 5, skip sunset machinery).
- **G2** Paid-but-no-result contract: (a) full request validation before
  `/settle`; (b) tool response persisted in the settlement record, replayed to
  honest retries and claim-race losers with the original PAYMENT-RESPONSE;
  (c) post-settle execution failure → bounded free re-execution (≤24h, N≤3)
  against the same claimed nonce; (d) "already used" on settle-retry maps to
  success ONLY with our D1 record; else receipt-pending + reconciliation
  backfill from on-chain `AuthorizationUsed` events. Race test asserts both
  racers receive IDENTICAL 200 bodies.
- **G3** Idempotency keyed `(payer, nonce)`: migration `UNIQUE(payer, nonce)`;
  DO id = `hash(from ‖ nonce)`; claim state machine
  `claimed → settling → settled | failed` with DO-alarm lease expiry so a
  crashed isolate cannot wedge a nonce.
- **G4** Fail-closed breaker + facilitator quota = DoS amplifier → hard
  structural gate before any facilitator call (valid base64/JSON within size
  caps, single header only, exact field match vs stamped requirement, 32-byte
  nonce, sane time window, `asset` EVM address on `eip155:*`, concrete `payTo` —
  never role constants); local ecrecover prefilter for plain 65-byte EOA
  signatures only; 6492/1271 skip straight to facilitator; per-IP/per-payer
  rate limit on the verify path.
- **G5** `validBefore ≥ now + settle_margin` (~30s) at verify; string-timestamp
  golden vectors.
- **G6** Price-change race: stamp issued requirements with extension
  `{mac: HMAC(requirement ‖ iat, worker-secret), iat}` (spec §5.1.2: clients
  must echo server extension info; may append, cannot delete/overwrite); echo
  verified against the MAC'd copy within `maxTimeoutSeconds` grace; previous
  config generation stays valid through grace.
- **G7** Reconciliation: hourly cron reconciles D1 settlements vs on-chain
  `AuthorizationUsed`/`TransferWithAuthorization`; backfills receipt-pending;
  `GET /supported` health probe asserting our scheme+network; alarms on breaker
  state changes and verify/settle failure-reason counters (spec §9 taxonomy
  vendored as constants, exhaustive match).
- **G8** CDP tier/limits/fee-free confirmation/ToS-sanctions findings recorded
  at Stage 0; breaker thresholds sized to tier; mainnet enable via KV config
  gate (instant flip AND retreat, no redeploy; `[vars]` holds defaults only);
  KV ≤60s eventual propagation documented in runbook.
- **G9** Full envelope types: `PaymentRequired {x402Version, error?, resource
  (ResourceInfo: url, description?, mimeType?) REQUIRED, accepts, extensions?}`,
  `PaymentPayload.accepted` echo, optional `payload.resource` (url must match
  route when present), `VerifyResponse {isValid, invalidReason?, payer?, extra?}`,
  `SettleResponse {success, errorReason?, payer?, transaction REQUIRED, network
  REQUIRED, amount?, extensions?}` — spec-exact nouns.
  **AMENDED (Stage-0 audit, verified vs vendored §6.1):** settle-before-serve is
  a non-default payment flow ⇒ every issued requirement MUST carry
  `accepts[].extra.paymentFlow = "upfront"` and
  `extra.assetTransferMethod = "eip3009"` (both protocol-reserved keys, §6.1);
  undeclared/unrecognized flows make conforming clients SKIP the requirement.
  Deviation note: spec's literal `upfront` ordering is settle → resource →
  respond with "/verify not part of this ordering"; we additionally call
  facilitator `/verify` before `/settle` as the G4 quota guard — a wire-invisible
  local step, satisfyin the §6.1 invariant (a check before execution). Also
  recorded: spec §6.1 says clients SHOULD prefer `authorization` when a
  resource offers both flows — we offer only `upfront` (revenue finality
  before execution), an accepted interop trade-off, revisit if client
  adoption data argues otherwise.
- **G10** Wire/impl nits: preflight `Access-Control-Allow-Headers:
  PAYMENT-SIGNATURE` (Expose alone breaks browser clients); reject duplicate or
  case-variant payment headers (400); replay-persist ≤256KB (larger ⇒ marked
  non-replayable); `alloy-primitives` U256; `#![deny(clippy::unwrap_used,
  expect_used, panic)]` on the payment path (a panic aborts the Worker request);
  nightly Rust↔TS differential fuzz; CDP JWT signing from WASM via
  `ed25519-dalek`/`p256` (`ring` does not build for wasm32); exactly-32-byte
  nonces at the structural gate.

## Stages (each ends: tests green + /cross-verify panel audit + user gate)

**Stage 0 — Decisions, baseline, spec pinning.** Branch `feat/x402-v2`
(✓ 2026-08-19); vendor specs + SPEC-VERSION (✓); HTTP-level legacy snapshot
e2e BEFORE refactoring; CDP secret; KV kill-switch design; reviews committed
(✓ this file); ▸ `0002_settlements.sql` with `UNIQUE(payer, nonce)` + status
state machine ▸ legacy paid-traffic measurement → sunset-vs-hard-cut decision
recorded ▸ CDP tier/limits/fees/ToS findings ▸ KV propagation caveat ▸ canonical
repo pinned + `coinbase/x402` historical note (✓ in SPEC-VERSION).

**Stage 1 — v2 types in m2m-core.** `x402v2` module (decimal-string amount →
U256; Base64 codec with size caps; golden vectors) ▸ full envelope per G9 ▸
string-timestamp vectors ▸ 32-byte nonce rule ▸ alloy-primitives + panic-deny
lints.

**Stage 2 — Crypto conformance.** Bidirectional vectors (TS→Rust AND Rust→TS);
domain-name divergence (Sepolia "USDC" vs mainnet "USD Coin"); v-normalization
(0/1 vs 27/28); expiry boundaries; `value == amount` (fix current `>=`);
error-taxonomy mapping to spec strings ▸ validBefore-margin vectors ▸
6492-suffix/1271-payer detection vectors (pass-through, not local failures) ▸
nightly differential fuzz.

**Stage 3 — Edge worker `/v2/` wire flow.** Header-normative 402 (body
decorative); client-owned nonce (NonceGuard demoted to legacy); CAIP-2
everywhere; well-known/llms.txt/openapi/mcp.json updated; official-client e2e
vs `wrangler dev` ▸ HMAC-stamped requirements + echo-vs-stamp verification ▸
CORS Allow+Expose ▸ duplicate/case-variant header rejection ▸ structural gate +
rate limits in front of facilitator ▸ `payload.resource.url` match.

**Stage 4 — Facilitator settlement (Base Sepolia).** Sequence: structural gate
→ `/verify` → full request validation → DO claim (state machine + alarm lease,
id `hash(from‖nonce)`) → `/settle` → execute → persist response → respond.
Failure-matrix fixtures; KV breaker fail-closed sized to CDP tier; live Sepolia
smoke via `paytest`-v2 ▸ replay path serves stored responses; already-used
semantics per G2 ▸ LEGACY ROUTE REWIRED through this pipeline +
`Deprecation`/`Sunset` headers ▸ cron gains on-chain reconciliation +
`GET /supported` probe + alarms.

**Stage 5 — SDK + staged rollout.** SDK v2 helpers mirroring the spec flow
(old SDK importable unchanged); staging e2e → prod v2-disabled → enabled →
mainnet via KV config gate; AGENTS.md/DEPLOY.md/openapi updated incl. the
published paid-but-failed contract; hard-cut legacy if Stage 0 measured ~zero.
**Mainnet flip only on the operator's explicit go.**

## Test gate for Stage 1

Legacy snapshot e2e · same-(payer,nonce) race → one settle + IDENTICAL 200
bodies · different payers same nonce → both succeed · paid-then-execute-fail →
free re-exec window then stored-failure replay · already-used without local
record → receipt-pending + cron backfill · validBefore-margin rejection ·
price-change mid-flight: old MAC accepted in grace, tampered rejected ·
duplicate/case-variant headers rejected · preflight CORS allow+expose ·
quota-DoS: invalid spam never reaches the facilitator stub, 6492 does ·
crashed-claim lease expiry frees nonce · >256KB non-replayable · facilitator
failure matrix · malformed-input fuzz (no panics).
